## 参考示例 (Examples)

英文：
Host: So let's talk about AI agents. Everyone's building them, but nobody seems to agree on what an agent actually is. What's your definition?

Guest: Yeah, it's a great question. I think, um, at the most basic level, an agent is just an LLM with access to tools and a loop. Right? So instead of the user typing a question and getting an answer, the model gets to decide what to do next. It might call an API, it might search the web, it might write some code and then check if it runs. And it keeps doing that until it decides the task is done. That's really all there is to it — the "agentic loop."

Host: So the magic isn't in the model architecture, it's in the control flow around it?

Guest: Exactly. The model is the same GPT-4 you're already using. The difference is you give it a while-loop and a set of tools, and you let it run. What makes this powerful is composability — you can chain these things together, have one agent's output feed into another agent's input. And that's where things get really interesting.

中文：
主持人：今天我们来聊聊 AI 智能体。现在好像所有人都在做智能体，但大家对"智能体到底是什么"这件事，居然还没达成共识。不如先请你说说你的定义？

嘉宾：这个问题问得好。我觉得，最基础地来看，智能体就是一个大语言模型，加上工具调用能力，再加上一个循环。就这么简单。平常我们跟模型对话，是你问一句、它答一句。但智能体不一样——模型会自己决定下一步该做什么。它可能会去调一个 API，可能会去搜索网页，也可能会写一段代码然后检查能不能跑通。它会一直这样循环下去，直到判断任务完成了。这就是所谓的"智能体循环"，其实没有更复杂的东西了。

主持人：所以关键不在于模型架构本身，而在于模型外面的这套控制流程？

嘉宾：完全正确。模型还是你正在用的那个 GPT-4，没有任何变化。区别在于你给了它一个 while 循环和一套工具，然后让它自己跑起来。这件事真正强大的地方在于可组合性——你可以把多个智能体串起来，让一个智能体的输出直接喂给下一个智能体。到了这一步，能做的事情就非常有意思了。

英文：
Guest: I want to talk about something that doesn't get enough attention, which is evaluation. Everyone is so focused on building — building models, building infrastructure, building products. But how do you know if what you built is actually good? In my experience, most teams I talk to don't have a real eval pipeline. They'll do some vibe checks, maybe look at a few outputs, and call it a day. That works for a demo. It does not work when you're trying to ship a product that people rely on.

Host: So what does a good eval pipeline look like?

Guest: It starts with having a golden dataset — a set of inputs and expected outputs that you know are correct. This doesn't have to be huge; even a hundred well-curated examples can tell you a lot. You run your model against this dataset every time you make a change — a prompt tweak, a model upgrade, whatever — and you track whether you're getting better or worse. The second piece is LLM-as-judge. For more subjective tasks where there isn't a single right answer, you can use a stronger model to evaluate your model's outputs. It's not perfect, but it's way better than nothing, and it catches regressions that you'd never notice by eyeballing a few examples.

中文：
嘉宾：我想聊一个关注度远远不够的话题——评测。现在所有人的注意力都在"造东西"上面，造模型、造基础设施、造产品。但你造出来的东西到底好不好，你怎么知道呢？就我的经验来看，大部分团队其实没有一套正经的评测流程。他们的做法就是靠感觉看一看，翻几个输出瞅两眼，觉得差不多就行了。做 Demo 这么搞没问题，但你要交付一个用户真正依赖的产品，这种方法是完全行不通的。

主持人：那好的评测流程到底应该长什么样？

嘉宾：首先你得有一套"金标准数据集"——就是一组你已经确认正确的输入输出对。规模不需要很大，哪怕只有一百个精心整理的样本，也能告诉你很多信息。每次你做任何改动——调个提示词、升级个模型、不管是什么改动——你都要拿这个数据集跑一遍模型，然后跟踪结果到底是变好了还是变差了。第二个关键手段是"LLM 当裁判"。对于那些比较主观、没有唯一正确答案的任务，你可以用一个更强大的模型来给你的模型输出打分。这个方法不是完美的，但绝对比什么都不做要强得多。而且它能帮你发现很多问题——那些你光靠肉眼翻几个例子根本不会注意到的性能回退，都能被它揪出来。
