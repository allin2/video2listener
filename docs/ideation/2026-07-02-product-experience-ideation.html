Ranked Ideas

1 管道可视化控制台 进度反馈 Conf: High

用 SSE 替换 2 秒轮询，前端渲染分阶段管道视图。每个阶段一个节点（下载→转写→清洗→翻译→TTS→合并），蓝色=进行中带 spinner，绿色=完成带耗时，红色=失败。点击节点展开该阶段日志。借鉴 GitHub Actions workflow 可视化模式。

为什么重要：用户最频繁的体验就是等待。从"看着一行行日志滚"变成"看一眼就知道在哪、还要多久"，是把焦虑变成可控感的核心杠杆。SSE 同时消除轮询延迟和无效请求。

Basis: direct: index.html:378-395 当前轮询只是文本展示；external: GitHub Actions CI pipeline 可视化是业界标准

2 一键从失败阶段恢复 错误恢复 Conf: High

失败时不丢弃进度。利用已有的文件检查点（transcript_clean.txt、script_zh.txt 等）判断哪些阶段已完成，在错误卡片上展示"已完成：下载/转写"+"失败于：TTS 合成 Segment 18"，并提供"从此阶段重试"按钮，跳过已成功的阶段。

为什么重要：当前整个 pipeline 报错后，用户除了看一条错误消息什么都做不了。30 分钟的进度白白浪费。利用已有的 check_stage_file 机制，这个功能的边际成本极低。

Basis: direct: state.py:38-57 check_stage_file 已实现每个阶段的文件标记；orchestrator.py:356 异常处理只记录 fail，不暴露已完成阶段

3 自定义确认弹窗 + 直接下载 提交流程 Conf: High

把原生 confirm() 替换为自定义 modal，弹窗中显示上次处理信息、直接提供"下载已有文件"按钮和"重新生成"按钮。支持键盘操作和移动端触摸。消除浏览器原生弹窗的阻断感。

为什么重要：原生 confirm() 在移动端尤其糟糕，而且当前弹窗里完全没有利用返回的 output_path——用户确认了还得等新任务跑完才能下载。这是最小的改动产生最大的体感提升。

Basis: direct: index.html:447-449 confirm(data.message) 原生弹窗无下载入口；server.py:214 返回了 output_path 但前端未使用

4 任务可取消 任务管理 Conf: Med

在进度卡片上添加"取消"按钮。设置 threading.Event 中断标志，管道在每个阶段开始前和 TTS 每段合成前检查标志。取消后保留已完成文件，DB 状态设为 cancelled，前端显示"已取消"并提供"恢复"选项。

为什么重要：当前一旦提交就失去控制权。用户选错模式、想换视频、或看到进度太慢，只能等它跑完或杀进程。取消是产品体验的基本权利。

Basis: direct: orchestrator.py:67-68 已有 _active_tasks + threading.Lock 锁机制，可在检查点扩展；external: yt-dlp、ffmpeg 等工具都支持 Ctrl+C 中断

5 多标签任务历史面板 任务管理 Conf: Med

新增 GET /api/tasks 端点，列出所有历史任务（从 DB 查询，合并内存状态）。前端增加"历史"标签页，表格显示视频标题、模式、状态、时间、文件大小，支持下载/删除。结果卡片展示文件名、大小、预估时长等元信息。

为什么重要：当前你一刷新页面，刚生成的文件就"消失"了——没有地方查看/下载过去的结果。一个用户每天 1-2 个视频，一周就积累十几条记录。历史面板把"一次性工具"变成"持续使用的个人播客库"。

Basis: direct: server.py 当前无历史端点，DB 中已有完整的 episode 记录可用；merger.py:320 多 Part 文件只存了 [0]

6 1Password 风格密钥管理 提交流程 Conf: Med

API Key 输入框增加显示/隐藏切换按钮、一键复制。localStorage 保存区域增加醒目的安全说明（"密钥仅存于此浏览器本地，不会上传"），输入框旁边增加小问号图标 hover 显示说明。TTS 音色选择旁提供试听按钮（播放 5 秒示例）。

为什么重要：用户每次打开页面都要面对"我要把密钥填进这个本地工具安全吗"的心理摩擦。增加可见的安全说明和标准的密钥输入 UX ，消除这种不安。

Basis: direct: index.html:254-262 密钥明文存 localStorage 但只有一行小字提示；external: 1Password/密码管理器 UI 模式是行业标准

7 提交前客户端校验 提交流程 Conf: High

点击"开始处理"时前端先校验：YouTube URL 格式（支持 youtu.be / watch?v= / 纯 ID）、模型是否已选择、至少 LLM API Key 已填写。不合法时在对应字段旁标红并显示提示文字，焦点移到第一个错误字段。避免提交到服务器才报错。

为什么重要：零成本消除一大类用户错误。当前未选模型提交 → 服务器用空字符串尝试翻译 → 报错。这个校验能拦截所有当前已观察到的无效提交。

Basis: direct: index.html:423-425 只检查 URL 非空，不校验格式；server.py:175 空 model 字符串仍会尝试使用
