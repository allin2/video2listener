PRODUCT REQUIREMENTS · V1.0

同一个视频，多种音频输出模式

让同一 YouTube 视频共享下载、转写和清洗资产，同时为忠实翻译版、中文播客版、精华浓缩版分别生成并长期保留独立音频。

清晰度 96/100澄清轮次 1只按模式区分版本状态：可进入开发

已确认的产品决策

  • 全部复用：元数据、原始音频、字幕/转写、清洗文本。
  • 多个版本共存：不同模式 MP3 永不互相覆盖。
  • 版本维度：当前仅使用 mode，不按音色或模型拆版本。
  • 相同模式：允许下载已有版本，只有明确操作才重新生成。

为什么要做

当前系统以 video_id 作为唯一记录，同一视频只有一个输出槽位。不同模式会共用相同脚本、TTS 目录和 MP3 路径，导致模式信息混乱、旧版本被覆盖，也无法证明复用了源资产。

KISS 决策：不复制大体积源文件，只新增轻量的模式版本层。

目标用户流程

提交 video_id + mode
        │
        ├── 视频源不存在
        │     下载 → 转写 → 清洗 → 创建所选模式版本
        │
        └── 视频源已存在
              ├── 相同模式已完成 → 下载已有 / 明确重新生成该模式
              └── 当前模式不存在 → 提示复用源资产 → 创建新模式版本
                                               翻译 → TTS → 合并

数据设计

保留 episode 作为共享视频源记录；新增 episode_variant 保存模式版本。这样迁移成本低于拆成两套全新表。

表唯一键职责
episodevideo_idURL、标题、下载、字幕、转写、清洗文本和源状态。
episode_variant(video_id, mode)模式、译文、摘要、TTS、MP3、版本状态和错误。

episode_variant 建议字段

id, video_id, mode, status,
script_zh_path, summary_path, tts_text_path,
tts_dir, audio_zh_path, error_message,
created_at, updated_at,
UNIQUE(video_id, mode)

文件布局

data/<video-title>/
├── metadata.json                 # 共享
├── source_audio.wav              # 共享
├── captions_en.json              # 共享
├── transcript_clean.txt          # 共享
└── variants/
    ├── faithful/
    │   ├── script_zh.txt
    │   ├── summary.json
    │   ├── tts_segments/
    │   └── output.mp3
    ├── podcast/
    └── condensed/

模式重生成只能清理对应 variants/<mode>，禁止删除共享源文件或其他模式目录。

接口行为

查询GET /api/videos/{video_id}/variants
创建POST /api/process，传入 mode 与明确的 variant_action
下载GET /api/download/{video_id}/{mode}
状态任务键改为 video_id:mode，允许同视频不同模式独立显示。

状态与历史记录

  • 被复用的下载、转写、清洗显示“已复用缓存”，而非重新计时。
  • 历史记录按视频聚合，展开后显示各模式下载按钮。
  • 同模式正在运行时阻止重复提交；不同模式可排队，但默认避免并发占满 API。
  • 删除某模式只删除该版本；删除视频源必须二次确认并删除全部版本。

迁移策略

  1. 幂等创建 episode_variant 表。
  2. 将现有 episode.mode、译文、TTS 和 MP3 注册为对应模式版本。
  3. 采用“移动前校验、临时目录、原子重命名”；任何失败保留原文件。
  4. 读取逻辑短期兼容旧路径，新写入一律使用 variants/<mode>。
  5. 迁移完成并验证后，再移除旧表中的模式输出字段依赖；首版不必删列。

验收标准

  • 同一视频首次生成时执行下载、转写、清洗。
  • 第二种模式不再调用下载和转写，进度明确显示三个复用阶段。
  • 三种模式可同时存在并分别下载，文件内容和路径互不覆盖。
  • 忠实翻译版必须覆盖全部输入批次，保留关键数字、案例、步骤、限定条件与结论；不得夹带连续英文原文或重复双语段落。
  • 中文播客版保留核心事实和逻辑，但允许删除口头禅、重复内容并按收听体验重组；不得与忠实版脚本完全相同。
  • 精华浓缩版聚焦最重要观点、论证和案例，内容量目标为忠实版的 30–50%；原视频超过 60 分钟时优先控制在 20–30 分钟。
  • 翻译任一批次失败、返回空内容或质量硬门禁失败时，任务必须失败并停止 TTS，禁止用部分译文或英文原文生成“完成”音频。
  • 同模式再次提交时提供“下载已有”和“重新生成该版本”。
  • 不同模式提交时文案明确为“创建新模式版本”，不使用泛化的“重新生成”。
  • 重生成一个模式不会改变其他模式的文件、状态、时间和下载链接。
  • 服务重启后可从共享文本或模式阶段恢复。
  • 旧数据迁移后仍可下载，数据库迁移可重复执行。

执行阶段

阶段工作交付物
1 · 数据层新表、迁移、模式目录、兼容读取幂等数据库迁移及测试
2 · 管道共享源状态、模式状态、定向清理与恢复模式隔离的编排器
3 · API/UI模式感知提示、状态键、下载、历史展示完整交互闭环
4 · 验证三模式矩阵、失败恢复、旧数据迁移、文件校验回归测试与运行验证

范围边界

本期包含：按模式管理版本，共享所有模式无关资产。

本期不包含：同模式多音色版本、同模式多模型版本、版本历史快照、多人权限与云端对象存储。
